## 修正：JS pdata ≠ Java pdata（用户指出，已按此重做）

反编译 KubeJS 确认：`dev.latvian.mods.kubejs.core.mixin.common.EntityMixin` 里是
`private CompoundTag kjs$persistentData` + `saveKJS/loadKJS`，即 **KubeJS 自己的一格存储**；
`Entity#getPersistentData()` 是 ForgeData。两者互不相通 —— 所以第一版「Java 写 ForgeData、
`entity/spawn.js` 读 `entity.persistentData.customData`」是断链的（副本怪会丢等级/变体/末影饰品）。

改成 Java 侧 API：
- 新增 `api/DungeonMobData`（ForgeData 键 `FastDungeon`，字段 type/wave/level/xp/xpup/killtarget/
  variant/enderbonus-JSON/spawnx,y,z），对外 `FastDungeon.getMobSpawnData(entity)`；
  删掉 Java 里所有 `Instance`/`customData` 写入，`collectArenaMobs`/死亡处理/关服清理全改读它。
- `entity/spawn.js`：先 `$FastDungeon.getMobSpawnData(entity)` 拿副本数据（level>0 才覆盖
  moblevelnum、variant、enderBonusJson→NewMobEntityEnderBonus），拿不到才走原来的
  `entity.persistentData.customData` 老路（给非副本写入方留兼容）。
- `DungeonMob.level` 缺省改为 **0 = 未指定**，JS 侧 `if (level > 0)` 才覆盖，否则保持随机等级。
- `DungeonChatLogEnabled` 现在只在 ForgeData，脚本查改走
  `FastDungeon.isChatLogEnabled/setChatLogEnabled`（原来 JS 写 kjs pdata、Java 读 ForgeData 也是断的）。
- ForgeData 不同步客户端：`getMobSpawnData` 只在服务端有效，Jade 仍靠 `syncMobEntityData` 数据包。

## 修复：alex 没等级、血量只有 500

原因：`MobLevels.shouldTrack` 用了 `instanceof Monster`，而 KubeJS 的 `entity.isMonster()`
是 `!entityType.getCategory().isFriendly()`。`FastBossEntity extends PathfinderMob`，
所以 alex / phantom_hero / mysterious_black_cloaked_swordsman / zombie_summoner 全被漏掉 →
不走 MobLevelDef（alex 表里是 hp 100000），只剩 createAttributes 的 500 血，Jade 也没等级。

修法：改用 `!getCategory().isFriendly()`，并额外 `instanceof Player` 直接排除（PLAYER 是 MISC，会被误判）。
同时 `MobLevels.apply` 末尾补 `setHealth(getMaxHealth())`，兜住「实体早就存在、不会再跑 JS 钩子」的老怪。

遗留提醒：等级表里没有 `fast:phantom_hero` / `fast:boss` 条目，它们会走 `default`（20 + 6/级），
这是迁移前就有的行为；要让它保持 createAttributes 的 800 血，得在 `startup_scripts/entity/mob_level.js` 加条目。

## 新增 fast:boss_arena 维度 + BOSS 战首通实例化

需求：新维度，方块不可交互/破坏；BOSS 战首通前都在这个维度里的战斗结构内打，通关/失败回来，
死亡在结构里重生；首通后回原世界原地开打；要有兜底返回手段。

实现（`com.main.fast.arena` 14 个类 + 维度 JSON）：
- 维度：虚空超平坦 + 末地天空 + 固定正午 + 不刷怪，`data/fast/dimension{,_type}/boss_arena.json`。
- 场地：代码生成（地板/围墙/嵌灯/中心地标），每场一个 512 间距的槽位，Y=64。
- 流程挂在 `DungeonKeys`：未首通 + 已注册的 BOSS 副本 → `ArenaManager.startFirstClear` 把整场副本开在竞技场；
  `DungeonEndEvent` → `finishRun` 记首通 + 原路送回。
- 首通记录：`ArenaProgress`（SavedData，按玩家 UUID，存主世界）。
- 保护：只拦「会改方块」的物品 + 挖掘速度归零，避免误伤施法/开枪（踩过坑：整块取消 RightClickBlock 会废掉法术）。
- 兜底：命令 / 每秒扫滞留者 / 登录扫 / 返回点失效改世界出生点 / 掉虚空捞回。

待真实机验收：维度能否生成、场地外观、BOSS 与计时是否正常、死亡重生、返回。

## 竞技场按用户思路重做：删兜底、10 秒存活检测、禁传送、奖励回原点

用户明确否掉了原先的「四层兜底」，改成单条判定：
- 删掉 `/fast arena leave`（含 `FastArena.leave`/`ArenaManager.evacuate`）、tick 滞留扫描、
  登录扫描（`onLogin`/`PlayerLoggedInEvent`）、`returnTo` 的多级回落（记录点不可用改世界出生点、异常改送）。
- 新 `ArenaManager.tick`：**每 200 tick（10 秒）** 一次
  ①`DungeonManager.getInstance(key)==null` → 结束送回；②实例 ACTIVE 且 `getArenaMobs()` 空 → `stop()` 删副本并送回；
  ③玩家在竞技场但 `RUNS_BY_PLAYER` 没有 → 送回主世界出生点。`PREPARING` 阶段不判（否则倒计时里就把副本删了）。
- 新 `ArenaTeleportLock`：`EntityTravelToDimensionEvent`（进出都拦）+ `EntityTeleportEvent` 父类
  （/tp、/spreadplayers、末影珍珠、紫颂果、末影人）。唯一放行 = `ArenaManager.internalTeleport > 0`，
  `teleportInternal()` 是所有进出场的唯一入口。**新增任何传送都必须走它**。
- 奖励：`DungeonInstance.deferRewards`（竞技场开本后 `setDeferRewards(true)`）→ `complete()` 只 roll 不投放，
  存 `deferredRewards`；`ArenaRun` 新增 `originDimension/originPos`，传回后在原点方块上方 1 格生成。
- 掉落物：结束不立刻传送，`PENDING` 挂 3 秒（60 tick，`tickPendingReturns` 每 tick 推进）→
  `collectDrops` 收场地 AABB 内 ItemEntity → 和奖励合并 → 一起打包带回原点。
- `CreatePackages.spawn` 改成每 9 格一个包裹循环（原来 >9 件会丢奖励）。

## 竞技场：不做传送封锁，改成「空场清理」
用户改主意：正常位移全部放行，不禁止传送。删掉 `ArenaTeleportLock`（及 `ArenaManager.internalTeleport` 计数），
改为 `cleanupIfEmpty(server)`：竞技场维度里没有任何玩家 → 依次 摘 run → `abandon()` → `DungeonManager.stop()`。
`abandon` 不传送、不发奖励，只清索引/还原重生点/释放槽位（`DungeonEndEvent` 里 `RUNS_BY_INSTANCE` 已无该 key，
`finishRun` 直接 return，所以不会走 3 秒延迟和奖励投放）。
触发：`PlayerEvent.PlayerChangedDimensionEvent` 立刻调一次 + 每 tick 兜一次（`/tp` 跨维度不触发维度事件）。
