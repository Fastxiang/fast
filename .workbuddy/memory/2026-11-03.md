## 副本生命制（死的次数上限 + 重生点临时改到副本）
需求：进副本时重生点临时设到副本；每人 3 条命（多一个人 +3）；死满 3 次副本失败 →
清怪、等 5 秒、自动送回、还原重生点。

实现（`dungeon` 包）：
- 新 `DungeonParticipant`：进入前的维度/坐标/朝向 + **当时的重生点**（dim/pos/angle/forced），
  提供 `teleportBack` / `restoreRespawn`。
- `DungeonInstance`：`State.FAILING`、`lives`、`failTicks`、`participants`；
  `putParticipant(participant, 3)` 每加一个人就 +3 命；`useLife()` 扣命。
- `DungeonManager`：
  - `start(...)` 登记 owner（7 参重载的 `registerOwner`，竞技场传 false）；
  - 每 20 tick `scanParticipants(instance)`：进入半径 100 的新玩家自动登记 +3 命 + 改重生点；
  - `onPlayerDeath`：扣 1 命，`<=0` → `fail()`（清怪 + 摘血条 + 120→100 tick 计时）；
  - `failAndReturn`：送回 + 还原重生点 + `DungeonEndEvent(FAILED)`；
  - `releaseParticipants(instance, teleportBack)`：**任何结束**都要还原重生点，只有失败才传送；
  - 玩家还躺在死亡界面没重生 → 存进 `PENDING_RETURN`，`onPlayerRespawn` 补送；
    重生点不生效（脚下不是床/锚）时 `onPlayerRespawn` 也会把人拉回副本。
- `DungeonHooks`：`LivingDeathEvent` 里玩家走 `onPlayerDeath`（不再走刷怪逻辑）；
  新增 `PlayerEvent.PlayerRespawnEvent` → `onPlayerRespawn`（跳过 endConquered）。
- `DungeonEndEvent.Reason` 新增 `FAILED`。
- 竞技场：`startFirstClear` 在改重生点**之前** `captureParticipant` 存进 `captured`，
  `start(..., announce=false, registerOwner=false)` 之后再 `adoptParticipants(instance, captured.values(), false)`；
  `ArenaManager.finish` 遇到 `FAILED` 只回收场地（人不重复送、奖励不发）。
- 语言键（实例 `kubejs/assets/fast/lang/zh_cn.json`）：`ender_bonus.instance.lives.{join,death,fail,returned}`。

坑：竞技场原本先 `setRespawnPosition` 再 `DungeonManager.start`，如果按默认让 start 登记 owner，
抓到的「原重生点」已经是竞技场 → 失败后会永远在竞技场重生。所以加了 `registerOwner=false` 开关。

## 修：第一次死亡副本就结束（竞技场空场清理误杀）
日志证据：
```
01:26:13.572  Fast_xiang 阵亡，剩余生命 2      ← 生命计对了
01:26:14.514  竞技场里已无玩家，清理副本       ← 0.94 秒后副本被删
01:26:18.053  在竞技场但既无副本也无怪物，送回
```
根因：`ArenaManager.cleanupIfEmpty` 是**每 tick** 跑的，判据是 `arena.players().isEmpty()`。
玩家「死亡→点重生」时 `PlayerList#respawn` 会先把旧实体从世界里摘掉、再生成新实体加回来，
**中间有一 tick 维度里一个玩家都没有**，正好被这个每 tick 的检查撞上 → 副本被当成人走空了。
（期间没有任何维度切换日志，人也确实一直在竞技场。）

修法：
- `EMPTY_GRACE_TICKS = 40`（2 秒）：连续 40 tick 都空才清理，`emptyTicks` 一旦有人就归零。
- 实例处于 `FAILING`（生命耗尽的 5 秒等待）时跳过清理。
- 记忆点：**任何「每 tick 判空」的清理逻辑都要给宽限**，死亡/重生/传送都有一 tick 的真空期。

## 失败等待 60 秒 + 手动跳过 + 重生点规则收敛
需求四条：失败空窗改 60 秒；失败期间空手潜行右键可立刻回去；进维度若副本不存在 /
正常失败都**不**回退重生点；副本维度里的重生点不重复记录、不当历史记录。

实现：
- `DungeonManager.FAIL_RETURN_TICKS = 1200`（60 秒）。
- 新增 `DungeonManager.trySkipFailWait(player)`：`isShiftKeyDown` + `mainHandItem.isEmpty()`
  + 实例处于 `FAILING` → `setFailTicks(0)`（下一 tick `tickFail` 就 `failAndReturn`）。
  入口挂在 `DungeonHooks.onRightClickBlock` 最前面，命中就 `setCanceled(true)` 并 return。
  ⚠️ 只覆盖 `RightClickBlock`：空手右键**空气**客户端连包都不发，服务端收不到。
- `ArenaManager`：`DEATH_GRACE_TICKS = 200` + 静态 `deathGraceTicks`，`ArenaHooks` 监听
  `LivingDeathEvent` 调 `onPlayerDeath`（只在竞技场里生效）；`cleanupIfEmpty` 每 tick 递减，
  >0 时 `emptyTicks` 归零直接 return。
- 重生点：
  - `DungeonManager.TRANSIENT_RESPAWN_DIMENSIONS` + `mark/isTransientRespawnDimension`，
    由 `ArenaDimensions` 静态块登记 `ARENA_KEY`。
  - `DungeonParticipant` / `ArenaRun.ReturnPoint` 各加 `respawnValid`：捕获时维度是临时的 → false，
    `restoreRespawn` 直接跳过（不动玩家当前设置）。
  - `releaseParticipants(instance, teleportBack, restoreRespawn)`：失败传 `(true, false)`；
    通关/超时 `(false, true)`。
  - `onPlayerRespawn` 的 `PENDING_RETURN` 分支去掉 `restoreRespawn`。
  - `ArenaManager.returnToLastEntry` 删掉 `setRespawnPosition(OVERWORLD, null, ...)`。
- lang：`lives.fail` 改 60 秒文案 + 新增 `lives.skip_wait`。

构建 27 秒通过，jar 已部署（md5 `47868429…`）。
⚠️ 失败不还原重生点意味着：玩家在竞技场失败后重生点仍指向竞技场，下次在任何地方死亡都会先
在竞技场站起来，再由 10 秒检测送回「上次进入副本的位置」。这是按用户要求保留的行为。

### 更正：失败**必须**回退重生点（上面理解反了）
用户原话是要修「失败结算后没有回退重生点」，不是要保留现状。最终实现：
- `DungeonManager`：`releaseParticipants` 恢复两参数（任何结束都 `restoreRespawn`），
  `failAndReturn` 传 `teleportBack=true`；`onPlayerRespawn` 的 `PENDING_RETURN` 也恢复还原。
- 新增 `arena/ArenaRespawnOrigin`（SavedData `fast_arena_respawn`）：按 UUID 持久化「进副本前的真实重生点」。
  `remember` 只在当前重生点**不在**临时维度时写（临时值不重复记录、不覆盖旧记录）；
  `restore` 取完即清。`startFirstClear` 在改重生点之前 `remember`。
- 回退点统一「持久记录优先，内存快照兜底」：`returnTo` / `abandon` / `returnToLastEntry` /
  `FAILED` 分支都先 `ArenaRespawnOrigin.restore`，失败再 `restoreRespawn(ReturnPoint)`。
  这样重启、副本被删、连续多把都能回到真正的床。
- `DungeonParticipant.respawnValid` 保留：捕获到的若是竞技场临时值，`restoreRespawn` 跳过，
  避免把临时值当历史写回去。

## 竞技场「斗兽场」样式（Huge Boss Arena 复刻）
先搜 GitHub 找现成 Boss 战地图：**没有**（全是插件/工具/datapack，成品建筑都在资源站）。
顺带确认 `F33RNI/FracturedReflections`（1.20.1 完整存档）、`Piccomaster/AcrossTheTime2`（GPL-3.0）
是仅有的完整地图仓库；转换工具 `JoshuaVandaele/Schem-File-to-Structure-Block-NBT-Format`（.schem→.nbt）。

目标资源 `Huge Boss Arena`（agagag，半径 60 圆形+观众席）三个来源全部拿不到：
- mcbuild.org `/download/schematic=1791` → 35 字节 `File not available or link expired.`（带 cookie/referer 也一样）
- minecraftschem.com `download.php?id=4202` → 跳 Shopify 商店页（424KB HTML）
- minecraft-schematics.com `/schematic/1777/download/` → 重定向到 Login
→ 改为**按描述复刻**，不依赖外部文件。

实现：
- `ArenaConfig` 加 `style`（`plain`/`colosseum`）与 `seats`（0~8）；`colosseum` 不写 seats 默认 4；
  `getOuterRadius() = radius + seats + 1`。
- `ArenaBuilder.build()` 分派 `buildPlain`（原逻辑）/ `buildColosseum`：
  圆形平台（r）→ 环形阶梯观众席（第 i 层在环带 (r+i-1, r+i]，顶面高 i）→ 外墙（环带 (outer-1, outer]，
  y=2 与 topY-2 每 6 格嵌灯）→ +Z 门洞（半宽 2、高 4，挖穿座位与墙并补通道地板）→ 中心灯。
- ⚠️ **场地外径不能超过 ~35**：`notifyPlayers` 用 50 格 AABB，半径 60 的角落 85 格收不到提示。
  所以 fast47 用 `radius:24, seats:4`（外径 29，角落 41）。
- `arena.js`：fast47 从 `ARENA_BOSSES` 挪出来单独注册成 colosseum；改回 `$FastArena.registerDungeon("fast47")` 即退回光板。
- 用 Python 按同一算法渲染了俯视/剖面预览（`.workbuddy/preview/arena_colosseum_{top,section}.png`）验证形状。

构建 26 秒通过，jar 已部署（md5 `ff45dd97…`）。

## 通关也走 60 秒等待 + 竞技场怪物回收
需求：通关改成和失败一样的 60 秒倒计时（可空手潜行右键跳过），但奖励包裹仍在外面结算时获得。
顺带修「突变末影人自己瞬移出场地→副本结束」。

通关等待：
- `DungeonInstance.State` 新增 `COMPLETED_WAITING`；`failTicks`/`tickFail` 统一改名
  `waitTicks`/`tickWait`（失败和通关共用）。
- `DungeonManager.complete()`：`isDeferRewards()`（竞技场）时不立刻结束，改设
  `COMPLETED_WAITING` + `SUCCESS_RETURN_TICKS=1200`，清怪、摘血条、播 `complete_wait`；
  **奖励在这里不 roll**。
- `finishComplete()`：到点/手动跳过后才 `ACTIVE.remove` → `releaseParticipants(false)` →
  `setDeferredRewards(DungeonRewards.roll(...))` → `DungeonEndEvent(COMPLETE)`，
  由 `ArenaManager` 回原方块投放包裹。普通副本仍走原来的「立即结算 + 原地生成包裹」。
- `trySkipFailWait` → `trySkipWait`（FAILING / COMPLETED_WAITING 都认，文案分两条）。
- `onPlayerDeath` 在 `COMPLETED_WAITING` 不再扣命；`cleanupIfEmpty` 跳过该状态（通关要结算奖励）。
- lang：`complete_wait`、`lives.skip_wait_complete`。

末影人瞬移：
- 根因（MutantMonsters 8.0.8 源码）：`MutantEnderman#teleportRandomly()` 是 ±24 格随机，
  `teleportToPosition()` 在虚空里向下找不到方块会把落点定在虚空底部；竞技场正好是虚空，
  它跳出去 → 掉出世界被 discard（不走 `LivingDeathEvent`）→ `ArenaManager` 的「怪空」判定结束副本。
- 修法：`ArenaManager.leashArenaMobs`，每 10 tick 扫一遍 ACTIVE 竞技场实例的 `getArenaMobs()`，
  离开 `innerRadius + 6` 或掉到 `FLOOR_Y - 6` 以下就 `teleportTo` 回中心 4~12 格的随机点，
  清掉速度和 `fallDistance`。
