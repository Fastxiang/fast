**关键结论**
- 祭坛外观 100% 由 `RendererAltar_of_Fire`（BER）绘制，`Altar_of_Fire_Model` 用 lionfishapi 的
  `AdvancedEntityModel`/`AdvancedModelBox`/`BasicModelPart`。`BasicModelPart` **不继承** MC 的 `ModelPart`。
- lionfishapi 是独立前置 `lionfishapi-3.0.jar`（modId `lionfishapi`，不在灾变 jar 内），
  已拷贝到 `libs/` 并在 build.gradle 用 `implementation fg.deobf(files("libs/lionfishapi-3.0.jar"))`。
- **`fg.deobf(files(...))` 对本地 jar 不会重映射**（deobf 产物只在 `deobf_dependencies/` 下为 curse/maven
  依赖生成）。所以 lionfishapi 里的 MC 方法名仍是 SRG：
  - `m_6973_` = setupAnim，`m_7695_` = renderToBuffer
  - 子类必须**同时**实现 mojmap 名与 SRG 名（不加 @Override），并补 `Model.renderToBuffer` 委托给 `m_7695_`
- Forge 47.4.0 **没有** `RegisterClientExtensionsEvent`（那是 1.20.2+/NeoForge）。
  1.20.1 注册 BEWLR 只能让 Item 类自己 `implements IClientItemExtensions`。
- `BlockEntityRenderDispatcher.context` 字段不可访问；BEWLR 里直接 `new MachineAltarRenderer(null)` 复用即可。
- `EntityModelSet` 的包是 `net.minecraft.client.model.geom`（不是 `client.model`）。

## 最终采用：Mixin 改烈焰祭坛（cataclysm:altar_of_fire）

用户拍板「回退新方块，直接 mixin」。实测 mixin 方案只需 2 个类约 90 行，比复刻渲染简单一个数量级。
**教训：一开始我误判难度。** 我以为改 `strength(-1,3600000)` 要在构造函数里动 final 字段，
其实属性链最后一环 `sound(...)` 是绝佳注入点，一次 @Redirect 就能改完。

### 新增文件
- `mixin/cataclysm/AltarOfFireNoSummonMixin.java`
  目标 `com.github.L_Ender.cataclysm.blockentities.AltarOfFire_Block_Entity`，
  @Redirect `tick` 里的 `ItemStack.getItem()`（SRG `m_41720_`）：若物品是 `cataclysm:burning_ashes`
  就谎报 `Items.AIR`，让 `== ModItems.BURNING_ASHES` 永不成立 → 不召唤、不拆周围方块。
  **不 cancel 整个 tick**，这样 `tickCount++` 仍在跑，顶部火焰动画不受影响。
- `mixin/cataclysm/AltarOfFireBlockMixin.java`
  目标 `com.github.L_Ender.cataclysm.blocks.Altar_Of_Fire_Block`，两个 @Redirect 打在 `<init>`：
  1. `m_222994_()`（noLootTable）→ 返回原 props 吃掉它，保住默认掉落表
  2. `m_60918_(SoundType)`（sound，链最后一环）→ 补 `strength(5,6)` + `requiresCorrectToolForDrops()`
- `data/minecraft/tags/blocks/{mineable/pickaxe,needs_stone_tool}.json` → 加 `cataclysm:altar_of_fire`
- `data/cataclysm/loot_tables/blocks/altar_of_fire.json` → 掉落自身

### 关键机制（查证过）
- `BlockBehaviour#getLootTable()`：若 `drops` 为 null，自动解析为 `<blockId>.withPrefix("blocks/")`，
  即 `cataclysm:blocks/altar_of_fire`；所以吃掉 `noLootTable()` 后只需补一份 loot table json 即可掉落。
- `Properties` 的 loot table 字段 = `f_60894_`；`BlockBehaviour` 的 = `f_60440_`。
- SRG 对照：`m_60913_`=strength，`m_60999_`=requiresCorrectToolForDrops，`m_60918_`=sound，
  `m_222994_`=noLootTable，`m_60916_(Block)`=lootFrom，`m_41720_`=ItemStack.getItem，`m_41619_`=isEmpty。

### 混合映射的注意点
mixin 类里**调用 API 用 mojmap 名**（`props.strength(...)`），只有 `@At(target=...)` 字符串用 SRG 名
（配 `remap = false`）。两边搞混会「找不到符号」。

### 【重要】构造器中 @Redirect 必须 static（已修复）

用户构建后进游戏发现烈焰祭坛仍挖不动。查游戏日志定位：

```
D:\Minecraft\异界随行诗\.minecraft\versions\otherworld_traveling_poems\logs\latest.log
[WARN] [mixin/]: Mixin apply failed fast.cataclysm.mixins.json:AltarOfFireBlockMixin
        -> com.github.L_Ender.cataclysm.blocks.Altar_Of_Fire_Block:
  InvalidInjectionException: @Redirect handler before super() invocation must be static
  in injector .../Altar_Of_Fire_Block::fast$keepLootTable
```

- 原因：整条 `Properties` 链是在 `super(...)` **之前**求值的，Mixin 规定这种位置的
  `@Redirect` 处理器**必须声明为 `static`**，非 static 会直接让整个 mixin 被丢弃。
- 修复：`AltarOfFireBlockMixin` 的两个处理器改成 `private static`。
- 对比：`AltarOfFireNoSummonMixin` 打在 `tick()` 里（super 之后），非 static 没问题，日志无报错 = 已生效。

**排错方法**：游戏 `.minecraft/versions/<实例>/logs/latest.log` 里 grep `mixin` + 模组 mixin 配置名；
`required: false` 会让失败静默，只能靠日志发现。该实例开了 mixin debug export（`.mixin.out/`）。

## 追加：取消烈焰祭坛的「放置物品」

用户要求把放物品的功能也关掉。`Altar_Of_Fire_Block` 反汇编确认：

- 右键走 `m_6227_` = `use(BlockState, Level, BlockPos, Player, InteractionHand, BlockHitResult) -> InteractionResult`
  （tsrg 已核对）。原逻辑：非潜行 + 手上物品 != asItem() 时，槽 0 空则放入 1 个（非创造扣 1），
  槽 0 有货则 `popResource` 弹出到地面并清空，返回 SUCCESS。
- `AltarOfFire_Block_Entity extends BaseContainerBlockEntity`，是 1 格 `Container`；
  `m_7013_` = `canPlaceItem(int, ItemStack) -> boolean` **恒返回 true** → 漏斗/投掷器也能塞。
- `m_6555_` = `createMenu` 返回 null，没有 GUI。

**两条都堵**：
- `AltarOfFireBlockMixin` 加 `@Inject(method="m_6227_", at=@At("HEAD"), cancellable=true, remap=false)`
  → `cir.setReturnValue(InteractionResult.PASS)`。用 PASS 而非 SUCCESS/FAIL，让右键「穿透」，
  手持方块时仍能对着祭坛旁边放置。
- `AltarOfFireNoSummonMixin` 加 `@Inject(method="m_7013_", at=@At("HEAD"), cancellable=true, remap=false)`
  → `cir.setReturnValue(false)`。只拦「放入」，不动 getItem/removeItem，已存货仍可取。

SRG 补充：`m_6643_`=getContainerSize，`m_8020_`=getItem，`m_6836_`=setItem，`m_7407_`=removeItem，
`m_7983_`=isEmpty（Container），`m_6211_`=clearContent，`m_7702_`=Level.getBlockEntity。
