## 女仆职业系统：AI 从 KubeJS 迁到 Java（fast mod）

### 结论
女仆 5 个职业的战斗 AI、连段、动画同步、命中特效全部进 Java；KubeJS 只保留「数据」：
末影饰品 → skillList、法术分类、法术标签，单向推给 Java。

### 新增 Java（`com.main.fast.maid`）
- `api/FastMaid`：KubeJS 唯一入口。`registerSpellType(spellId,type,cd,cdPerLevel)` /
  `registerSkillTag(spellId,tag)` / `setMaidData(entity, json)` / `getBuffCooldown(spellId,level)`。
  入参用 JSON 字符串（沿用 `FastDungeon.registerJson` 先例，避免 JS 对象转 Map 的坑）。
- `MaidSkillRegistry` / `MaidSkillData`：法术分类表、标签表、每个女仆的技能快照 + 冷却（按 gameTime，不落盘）。
  快照 10 分钟没刷新自动丢弃（`prune`，在 ServerTick 每 1200 tick 跑一次）。
- `MaidCombatPlanner`：决策顺序 = buff → 治疗 → 低血减仇 → 守卫嘲讽 → 职业攻击技能（aoe/等级打分）→ 武器行为。
- `brain/MaidCombatBehavior`：连段驱动器。**不写死法术 id**，段数读 `spell.getRecastCount()`，
  所以 triple_strike(3)、six_strike(6)、triple_slash 都能跑；结束连段时 `recasts.removeRecast(spellId)`。
- `task/MaidTaskBase` + `task/MaidTasks`：Warrior/Mage/Ranger/Guardian/Priest，
  UID 沿用 `fast:physical|magic|bow|shield|support`，另有隐藏的 `fast:physical2` 兼容旧存档。
- `event/MaidCastEvent`（抛给 JS 补仇恨）、`event/MaidCombatEvents`（BasicAttackPreEvent → 挥砍/魔法粒子 + 重击音效）。
- `MaidExtension`（`@LittleMaidExtension`）注册任务；`Fast.java` 注册 MaidCombatEvents。

## 追加：构建卡死的真正原因（22:39）
- 症状：`./gradlew --offline --no-daemon` 卡在 "Daemon will be stopped at the end of the build" 之后，
  daemon 日志停在 `The daemon has started executing the build`，**没有任何 `> Configure project` 输出**
  → 卡在 settings/配置阶段，不是编译。
- 排查：`--status` 显示 "12 busy and 1 incompatible Daemons could not be reused"（实际 0 个 java 进程，
  全是中断构建留下的僵尸条目），`~/.gradle/daemon/8.8/` 里堆了 702 个日志。
- **有效处理**：`rm -rf build .gradle`（项目内缓存）+ 删 daemon registry.bin，再 `clean build --offline --no-daemon`
  → **31 秒** BUILD SUCCESSFUL。清 daemon 日志/registry 只解决"12 busy"提示，真正卡住的是项目内 `.gradle`。
- 结论：以后卡在配置阶段先 `rm -rf build .gradle`，别只清锁文件。
