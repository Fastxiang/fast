## 第二十轮补 3 · 真凶是 JS 钳制（00:46）—— 重要教训

用户：「打开后有几秒是正常的，然后突然又变成截图的样子」。
→ 锁定 = 我的 `tfLayoutClamp` 用 `window.innerWidth/innerHeight` 写内联 maxWidth/maxHeight。

**根因**：`window.innerWidth/innerHeight` 走 `Size.getWindowSize()`，读的是
`Document.getContextDocument()`（**上下文文档**，不是当前文档）的 viewport.layout。
开屏头几秒上下文未稳定 → 拿到 0 → 函数 return → 面板按 stretch 正常显示（所以"几秒正常"）；
稳定后返回的可能不是本页（browser 模式）的视口，而是另一套坐标系里更小的数
→ 920px 面板被压扁（"突然变形"）。

**结论：锻造页不要 JS 钳尺寸**。它原本就不用 vw/vh，尺寸靠百分比 + stretch：
宽 = `.window{max-width:100%}`（相对 .screen 内容盒）；高 = `.screen{height:100%}` + stretch。
装不下由 `.content{overflow-y:auto}` + `.workspace{min-height:360px}` 滚动兜底。
`tfLayoutClamp` 降级为纯探针（只打 `[Fast/AUI] tf viewport observed=WxH`）。

> 对比：商店页（mode=gui）用 innerHeight 钳制是对的 —— 那是 gui 模式且当时上下文就是它自己；
> 这个 API 的「上下文文档」语义决定了它不能跨页面/跨模式乱用。
