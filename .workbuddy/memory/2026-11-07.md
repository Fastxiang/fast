- 结论：**是**。`DungeonManager` 里 `FAIL_RETURN_TICKS = 1200`、`SUCCESS_RETURN_TICKS = 1200`（注释写「60 秒」）；
  `DungeonInstance.State` 的 `FAILING` / `COMPLETED_WAITING` 共用 `waitTicks` + `tickWait()`，

## 修：突变末影人「瞬移出去副本直接结束」
反编译 MutantMonsters 8.0.8（`libs` 里没有，直接从实例 `mods/MutantMonsters-v8.0.8-1.20.1-Forge.jar` 解）确认：
- `MutantEnderman#teleportRandomly()` = ±24 格随机；`teleportToEntity()` 跟目标 ±16，**距离 > 100 时改
  `Vec3(target-pos).normalize()` 方向 8 倍** → 目标一动就是几十格。
- `EntityUtil.teleportTo`（仅在 `isClone()` 时才走）会从目标点向下找实心方块，虚空里没有 → 一路找到 `minBuildHeight`，
  再 `moveTo(minY+1)`；不是 clone 时 `teleportToPosition` 只调 `teleportTo`（顺带 `setPortalCooldown`）。
- `MutantEnderman$TeleportGoal`：`start()`/`stop()` 把 `f_19855_`（yOld）改成目标/自身 Y，再 `m_6034_(x,yOld,z)`（`moveTo`，不推包），
  动画各出现一次 —— 每次瞬移生效两三次。
所以「瞬移出场地 → 掉虚空换维度 → 被 Forge `canUpdate()` 删掉且不走 `LivingDeathEvent` →
`ArenaManager` 200 tick 那次「副本里已经没有怪物」判定」整条链是通的；
`ArenaManager.leashArenaMobs` 只在**本维度**扫，够不着已经换维度的怪。

修法（全在 `com.main.fast.dungeon.DungeonManager` 与 `arena.ArenaManager`）：
- `collectArenaMobs(ServerLevel, instance)` + `hasLiveArenaMobs(server, instance)`：存活判定改成**全维度**扫描；
  `ArenaManager` 的「怪空 → 结束」改用 `hasLiveArenaMobs`；`shutdown` 也按维度逐个清。
- `reclaimStrayMobs`（每 10 tick）：横向/竖向离中心 > `100 × 1.75`、或低于副本地板 16 格 → 拉回中心 4~12 格；
  在别的维度的先 `setPortalCooldown(0)` + `changeDimension` 再 `teleportTo`，清速度和 fallDistance。
- `onMobDeath` 加「已结算」标记（ForgeData `FastDungeonCountedDead`）+ 副本已结束时只落日志。
- `ArenaManager.leashArenaMobs` 保留为兜底（本维度内绕到观众席/墙外的怪），注释写清分工。

## 事故：启动崩溃 MixinTransformerError（02:14）
- 崩溃点：`fast.cataclysm.mixins.json:AncientRemnantProjectileImmunityMixin` 的 Redirect
  `fast$removeArrowImmunity` **0/1 命中** → `InjectionError` → `RegisterEvent`（灾变 `ModStructures`）加载时崩服。
- 根因：`CataclysmProjectiles.GET_DIRECT_ENTITY` 我写成了 `m_7639_`。用 javap 反编译灾变 3.31 的
  `Ancient_Remnant_Entity#m_6469_` 看到真实调用是 `DamageSource.m_7640_:()Lnet/minecraft/world/entity/Entity;`。
  （`m_7639_` 是 `getEntity()`，`m_7640_` 才是 `getDirectEntity()`。）
- 这个常量是**原本就存在的**（`EnderGuardianProjectileImmunityMixin` 也用它），属于既有 bug，不是本次副本修复引入的；
  源码里注释还把方法体写成了 `source.getDirectEntity()`，所以谁都没发现。
- 修复：常量改 `m_7640_` + 注释写清。重新 `clean build` 24 秒通过，jar 已部署（md5 `FA9EBE2B…`）。
- 教训：**改 mixin 注入点前必须 javap 目标类核对 SRG 名**，尤其是 `remap=false` 的那批。
