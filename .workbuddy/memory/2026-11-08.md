# 2026-11-08

## 灾变 boss 在副本/竞技场的问题调研（未改代码）

用户反馈：灾变 boss 会破坏方块、会飞，副本里玩家难打。要求先看灾变源码 + 副本现状再给方案。

### 灾变 3.31 源码结论（javap 反汇编，build/catdump2/bosses/）
- 上场的灾变 boss：fast43 Ignis、fast44 Netherite Monstrosity、fast45 The Harbinger、fast46 Ancient Remnant。
- 破坏方块统一是 `Level#destroyBlock(pos, false, this)`（SRG `m_46953_`），调用点：
  - Ignis：`blockbreak / ShieldSmashDamage / UltimateAttack`（tick 里按 `destroyBlocksTick==0` 触发）。
  - Netherite：`ChargeBlockBreaking / berserkBlockBreaking`（后者 `removeBlock` + 生成 `Cm_Falling_Block_Entity` 掀地板）。
  - Harbinger：`blockbreak / destroyBlock / destoryblock2`（`m_8024_` = serverAiStep 里）。
  - Ancient Remnant：tick 内按状态 + `Charge()`。
- **每条破坏路径都先判 `ForgeEventFactory.getMobGriefingEvent(level, this)`** → `EntityMobGriefingEvent` 可以
  `Result.DENY` 一刀切（零 mixin）。
- 四只都有 immune tag（`ignis_immune` / `harbinger_immune` / `netherite_monstrosity_immune` / `remnant_immune`），
  交集含 `barrier`、`bedrock`、`reinforced_deepslate`（换场地材质也能防破坏，但只对灾变有效）。
- 真飞行只有 The Harbinger（构造器 `new FlyingMoveControl(this,10,false)` + `createNavigation` 返回 `FlyingPathNavigation`）；
  Ignis/Netherite 是跳跃/冲撞，Remnant 钻地。Harbinger 无 `setNoGravity`。

### 副本现状（关键代码）
- 竞技场 `fast:boss_arena`：虚空 + 1 层地板 + 环形墙（wallHeight 6~9），**没有顶盖**；`ArenaConfig` 无 ceiling 字段。
- `ArenaProtection.onBlockBreak` 只对玩家生效 —— Forge `BlockEvent.BreakEvent` 只在 `ServerPlayerGameMode` 触发，
  mob 破坏 `Level#destroyBlock` 完全不经过。
- `MutantEndermanGriefGuard.onBlockBreak` 用 `event.getPlayer()` 判破坏者，对 mob 恒 null → 取消分支是死代码，只剩补洞。
- 补洞：每 5 tick、只补玩家 10 格内、固定 `polished_deepslate`；场地半径 24~32，站边上时补不到中心洞。
- 竖直 leash：`reclaimStrayMobs` 判 `Math.abs(dy) > NEARBY_RADIUS*1.75`（175 格），竞技场里等于没有上限。
- `ArenaManager.leashArenaMobs` 只在地板下 6 格/外径+6 拉回，也不限高。
- 首通后走普通副本（原世界原地开打），没有任何方块保护。

### 方案（待用户拍板，未实施）
1. `EntityMobGriefingEvent` 监听，副本怪 → DENY（覆盖灾变全部破坏点 + 苦力怕等）。
2. mixin `Level#destroyBlock`（m_46953_，remap=false）按 breaker 是副本怪 + 在竞技场 → `setReturnValue(false)` 兜底
   （覆盖不查 mobGriefing 的模组，如突变末影人）。
3. 飞行：优先扩 `leashArenaMobs` 加 Y 上限（配置 airLimit，默认 8）+ `ArenaBuilder` 可选 barrier 顶盖；
   若要近战可打，再 mixin Harbinger 的悬停高度（需读 `m_8024_` 的目标 Y 写法）。
4. 清理死代码：`MutantEndermanGriefGuard` 的 getPlayer 判断；补洞半径按场地半径。

## 实施（同日，已构建部署）

用户决定：场地翻倍 + 用 Forge 事件让灾变 boss 不破坏方块（不禁飞）。

- `ArenaConfig.DEFAULT` radius 24→48；`Instance/arena.js` 里 large 32→64、fast47 24→48（colosseum 外径 53）。
- `DungeonManager.notifyPlayers`：竞技场维度广播半径兜底到 110（原来调用点统一传 50，覆盖不到 64 半径场地）。
- 新增 `dungeon/DungeonGriefingGuard`：`EntityMobGriefingEvent` → 只对 `cataclysm:` 命名空间 + `DungeonMobData` 非空 +
  `DungeonManager.isEntityInInstance` → `Result.DENY`。覆盖灾变 11 个破坏点，零 mixin。
- `DungeonManager.isEntityInInstance(Entity)`：同维度 + 100 格 box。
- 构建成功（34s），jar 已复制到实例 mods/，MD5 `F8AE2E2E1D8DEB3BD943505816AFCC98` 两端一致。
- ⚠️ arena.js 是 startup 脚本，改后必须重启游戏（`/reload` 不重载）；换 jar 也必须完全退出游戏。
