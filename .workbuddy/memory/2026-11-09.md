### stardew_fishing 3.7 源码结论（vineflower 反编译，临时目录 sf_src）
- Forge 事件全在 `com.bonker.stardewfishing.server.event`：
  `StardewMinigameStartedEvent`（getIdleTime/TopSpeed/BarSize/LineStrength/TreasureChanceBonus/GoldenChanceBonus/ExpMultiplier/QualityBoost 全可写）、
  `StardewMinigameEndedEvent`（success/accuracy/gotChest）、`StardewMinigameModifyRewardsEvent`（`List<ItemStack>` 可增删）。
- **模组自带玩家属性**：`stardew_fishing:line_strength`(默认1)、`bar_size`(36)、`treasure_chance_bonus`(0)、

  客户端 `ClientProxy.openFishingScreen` 收到即开界面。**没有可取消的 Forge 事件能阻止这个包**。
- 结算入口 `FishingHookLogic.endMinigame(ServerPlayer, success, accuracy, gotChest, qualityBoost, rod)`；
  `giveRewards` 里先 `rewards.unlock()` 再加宝箱战利品，最后才 post `ModifyRewardsEvent`，所以事件里能安全 `add`。

## 修复：商店 tooltip 被货架物品压住（AUI 分层 z）

- 现象：悬停 tooltip「有时候」被物品图标戳洞/压住，面板背景却不会盖住 tooltip。
- 根因（反编译 AUI 1.2.7 + MC 1.20.1 核实）：`Base.resolveFlatDocumentBaseZ` = `1.0 + 扁平文档序号 × 251.25`；
  `<item>` 在此基础上 +150（模型）/ +200（装饰）/ +250.25（浮空）。商店前面只要还有 1 份扁平文档（HUD/toast），
  物品 z 就是 402.25，刚好越过原版 tooltip 的 z=400；面板 252 < 400 所以不挡 —— 完全对上现象。
  `RenderType.gui`/`RenderType.text` 的 setupRenderState 会把深度测试重新设回 LEQUAL，原先那句
  `RenderSystem.disableDepthTest()` 对 tooltip 实际无效（之前能用只是因为 z 恰好在前面）。
- 修法：`ShopTooltipState#clearPageDepth` —— 页面画完后先 `graphics.flush()`，再 `depthMask(true)` +
  `RenderSystem.clear(GL_DEPTH_BUFFER_BIT, ON_OSX)`（glClear 受写掩码和 scissor 限制，必须先关裁剪、开掩码）。
  清一次同时治好悬停那份和 Pin Tooltips 钉住那份（它 z≈401，也在这条线上）。
- 构建通过、已部署实例 mods（md5 32e15aa7…）。待进游戏验收：开场（只有 1 份文档）与 HUD 起来后分别悬停货架。

## JEI 获取方式分类：从 kubejsadditions 迁到 Java 自绘

### 根因
- `kubejs/client_scripts/jei.js` 用 kubejsadditions 的 `JEIAddedEvents`。debug.log 里
  `Registering categories: kubejsadditions:jei_plugin` 之后**没有** `fast:ender_chest` 分类，
  但 `Adding recipes: RecipeType[uid=fast:ender_chest]` 有 → 只注册了配方没注册分类，JEI 一条都不显示。
- 顺带：`Text.translate(key).getString()` 写在脚本加载阶段，语言表还没加载 → 拿到裸键名。

### 现在的做法（不再需要 kubejsadditions）
- Java：`com.main.fast.compat.jei` = `FastJeiPlugin`(`@JeiPlugin`，UID `fast:jei_plugin`) /
  `FastJeiCategory`(RecipeType `fast:acquire`，184x106 卡片) / `FastJeiRecipe` /
  `api/FastJei`（JS 唯一入口，不含任何 JEI 类型，没装 JEI 也能调）。
- JS：`jei.js` 只收集数据 → `$FastJei.clear()` + `$FastJei.registerJson(JSON.stringify([...]))`。
  描述用文本节点 `{t:键,f:兜底,a:[...]}`，**渲染时才翻译**。
- 卡片底画在 `getBackground()` 里（JEI 保证背景在物品槽之下），文字画在 `draw()`。
- 编译依赖：`compileOnly files("libs/jei-1.20.1-forge-15.20.0.129.jar")`（从实例复制，SRG 名不影响编译，
  因为只用 JEI 自己的方法名）。**不要**加 runtimeOnly：dev 运行时是官方名，SRG jar 会崩。
- 空 NBT 不要写成 `{}`：会让 JEI 当成「带 NBT 变种」，普通物品按 R 查不到（JS 与 Java 两侧都过滤）。

### 补：KubeJS 的 Rhino 不支持剩余参数（踩坑）
- `function f(a, ...args)` → `EvaluatorException: missing formal parameter`，**整份脚本不加载**
  （日志 `logs/kubejs/client.log` 里只有一行 `[ERROR] ! function ...#36`，latest.log 里看不到）。
- 用 `arguments` + `for` 收参；模板字符串、`for...of`、`Array.includes`、`Object.entries` 都没问题。
- 离线自检工具（build/ 下，含 rhino-forge 2001.2.3 解包 + gson + commons-lang3）：
  - `build/rhinochk/RhinoParseCheck.java`：用真实 `dev.latvian.mods.rhino.Parser` 解析脚本
  - `build/rhinochk/RhinoRunCheck.java`：stub `Java`/`Item`/`global` 后真跑一遍，打印推给 Java 的 JSON
  - 命令：`java -cp ".;gson.jar;lang3.jar" RhinoParseCheck|RhinoRunCheck <脚本路径>`
