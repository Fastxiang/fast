## 核心mod：新增 Boss「昔日勇者的幻影」(fast:phantom_hero)

- 实体 `BossPhantomHero`（继承 FastBossEntity，实现 RangedAttackMob），注册于 `FastEntities.PHANTOM_HERO`，属性在 Fast.java ModEntityRegisterEvents。
- 技能 AI：
  - `PhantomHeroComboGoal`：复用附属 mod 的 `FastSpellRegistry.TRIPLE_STRIKE`（物理三连击）/ `TRIPLE_MAGIC_MISSILE`（魔法三连击），近身用物理、远程用魔法；释放前 1 秒 `SkillIndicator.showSquareByRadius` 红圈预警，之后按 8/8/14 tick 三段节奏逐段 `spell.onCast(...)`（CastSource.MOB），技能期间速度锁 -9 / 击退抗性 +1。
  - `PhantomHeroSpellGoal`：随机释放 irons_spellbooks:fireball / icicle / lightning_bolt / magic_missile（4 级），同样 1 秒红圈预警。
  - `PhantomHeroBowAttackGoal`：复刻 Alex 的 `BossRangedAttackGoal`（10s 风筝 + 5s 停顿、12~16 格保持距离、横向绕圈、8 tick 拉弓），去掉了箭雨专属逻辑。
- 关键实现：让非玩家 Boss 使用铁魔法的 player 动画
  - playerAnimator 的自动播放链路 `PlayerAnimationAccess.getPlayerAssociatedData` 只接受 AbstractClientPlayer，但底层 `dev.kosmx.playerAnim.impl.animation.AnimationApplier`（构造/IAnimation、tick()、setTickDelta()、updatePart(partName, ModelPart)）是公开的。
  - `PhantomHeroModel`（HumanoidModel + ModelLayers.PLAYER）自己持有 AnimationApplier；服务端用 SynchedEntityData 同步「动画资源位置 + 自增序号」（序号保证同一动画重复播放也能触发同步），客户端用 `PlayerAnimationRegistry.getAnimation(rl)` + `KeyframeAnimationPlayer` 播放，并把结果写入 head/torso(=body)/rightArm/leftArm/rightLeg/leftLeg。
  - 部件名必须用驼峰规范名（json 的 right_arm 加载时被归一化为 rightArm）；`updatePart("torso", body)`。
  - `HumanoidModel.setupAnim` 末尾会 `hat.copyFrom(head)`，动画改完 head 后必须再 copy 一次。
  - 推进方式：在 `setupAnim` 里按 `entity.tickCount` 差值调用 applier.tick()（每游戏 tick 一次，帧率无关）；partialTick = ageInTicks - entity.tickCount（已从 LivingEntityRenderer 源码确认 ageInTicks = tickCount + partialTick）。
  - 动画资源：附属 `fast_irons_spellbooks_addition:attack1/attack3/attack4`（0.4/0.4/0.7s，正好等于法术 castTime 8/8/14 tick），铁魔法 `irons_spellbooks:continuous_thrust_one_handed` / `long_cast` / `instant_projectile`。
- 依赖：build.gradle 新增 `maven.kosmx.dev` + `implementation fg.deobf("dev.kosmx.player-anim:player-animation-lib-forge:1.0.2-rc1+1.20")`（与铁魔法 3.16.3 一致）。
- 资源：`assets/fast/textures/entity/phantom_hero.png`（由 alex.png 幽灵化调色生成）、lang `entity.fast.phantom_hero`=昔日勇者的幻影。
- 编译/打包均通过（build/libs/fast-1.20.1-forge-0.0.1.jar）。
- 注意：TripleMagicMissileSpell.getCastFinishSound() 里用 Minecraft.getInstance()，专门服务端会炸（原附属已有此问题，单机/整合服没问题）。

## 幻影勇者：第二轮修正（动画位移残留 / 提示圈 / 武器）

- **动画后头身分离的根因**：`AnimationApplier.updatePart` 会同时写 ModelPart 的旋转和**位移(x/y/z)**；而 `HumanoidModel.setupAnim` 只重置旋转 + 左右手的 x/z，不重置 head、body、双腿的位移（y 也不重置）。动画一旦写过位移就永久留在模型上。
  → 解决办法：`PhantomHeroModel` 构造时 capture 六个部件的静止位移，每帧 `super.setupAnim()` 之后、`updatePart` 之前统一 `resetOffsets()` 还原。
  → 另外模型实例在所有 Boss 间共享，加了 `currentOwner` 判断，换实体时重置 lastSeq/lastEntityTick/applier，避免多个幻影勇者互相串状态。
- **提示圈重写**（不再用 `SkillIndicator.showSquareByRadius` 那个方块正方形，它和技能判定无关）：
  - 新增 `skill/network/PhantomTelegraphPacket` + `skill/client/PhantomTelegraphRenderer` + `skill/api/PhantomTelegraph`，形状直接抄法术判定：
    - 物理三连击 = 扇形，半角 60°（`TripleStrikeSpell` 的 `halfAngle = Math.toRadians(60)`），半径 = 实体 `ForgeMod.ENTITY_REACH` 属性值（法术里 range 就是读这个属性，默认 3，幻影设为 4.5）。
    - 魔法三连击 = 直线长条（`TripleMagicMissileProjectile` 沿 `getLookAngle()` 直线飞，`setNoGravity(true)`，无追踪；速度 2.5/tick，EXPIRE_TIME=300tick），长度 = 到目标距离 + 6，clamp[8,40]。
  - 提示绑定施法者实体 id，客户端每帧重取 `position()` 和 `getLookAngle()` 水平投影 → 预警期间 Boss 转身红圈跟着转。
  - 顶点 y 用 `Heightmap.Types.MOTION_BLOCKING` 采样贴地（clamp ±2 格），扇形 40 段三角扇 + 描边；统一绕序避免背面剔除。
  - 动画 json 的 position 是**像素**单位（Blockbench 16 单位 = 1 格），直接写进 ModelPart.x/y/z，无需换算。
- **技能精简**：删掉 `PhantomHeroSpellGoal`（额外的铁魔法火球/冰锥/闪电箭/魔力飞弹），Boss 只剩：物理三连击、魔法三连击、弓箭普攻。
- **武器随技能切换**：原版 LivingEntity **不同步**生物手持物品，所以新增 `DATA_WEAPON`(byte) 同步，服务端 `setWeapon()` 换 ItemStack，客户端在 `onSyncedDataUpdated` 里换同一个 ItemStack。物理三连击=钻石剑，弓箭AI=弓，魔法三连击=空手。

## 幻影勇者：第三轮修正（近战判定范围 / 主手）

- **近战红圈对不上的根因（重要）**：`TripleStrikeSpell.onCast` 里算出的 `distance` **没有用于判定**，只用于 `distance < 0.5` 的必中分支。真正的范围限制只有 `caster.getBoundingBox().inflate(range)` 这个**轴对齐 AABB**，再用 `dot >= cos(60°)` 的锥形过滤。
  → 所以真实水平判定 = **轴对齐正方形 ∩ 120°锥形**，不是半径 range 的扇形。正方形半边长 = 施法者半宽 + range + 目标半宽(0.3)（AABB 相交判定）。
  → 旧版画半径 4.5 的扇形，实际正方形半边能到 5.1、对角 ~7.2 → "不在红圈也挨打"。
  → 修法：新增 `SHAPE_CONE_BOX`，渲染器用 Sutherland-Hodgman 把正方形按锥形的两个半平面裁剪（半角 h 的锥形 = 两个半平面交集，法线 = 方向向量旋转 ±(90°−h)）。ENTITY_REACH 从 4.5 降到 3.5。
  → 若要让判定真的变成锥形，需在附属 mod 的 TripleStrikeSpell 里把条件改成 `distance <= range && dot >= cos(halfAngle)`（会让玩家的三连击范围变小）。
- **武器在左手**：`Mob#getMainArm()` = `isLeftHanded() ? LEFT : RIGHT`，生物出生时有概率被随机成左撇子（LivingEntity 的 LeftHanded 数据位）。`ItemInHandLayer` 按 `getMainArm()==RIGHT` 决定主手物品渲染到哪只手臂，左撇子就渲染到左手。
  → 修法：`BossPhantomHero` 直接覆写 `getMainArm()` 返回 `HumanoidArm.RIGHT`、`isLeftHanded()` 返回 false。

## 幻影勇者：第四轮（近战判定治本 + 站桩）

- **近战范围治本（改了附属 mod，重要）**：不继续在核心 mod 侧画"方块∩锥形"去迁就那个怪判定，而是直接修 `TripleStrikeSpell.onCast` 的判定：
  - 原来：`caster.getBoundingBox().inflate(range)` 轴对齐 AABB 粗筛 + 3D `dot >= cos(60°)`，`distance` 没用于限距。
  - 现在：AABB 只当粗筛（`inflate(range + 1)`），真正判定改为**水平扇形**——
    `horizontalDistance <= range` &&（`< 0.5` 贴脸必中 || 水平 dot `>= cos(60°)`），
    角度也改用 lookAngle 的**水平投影**（lookX/lookZ），不再用含 pitch 的 3D dot。
  - 于是判定区域 = "以 position() 为中心、半径 = ENTITY_REACH、半角 60° 的水平扇形"，和红圈画的扇形**完全同源**。
  - 已用 Python 扫 80 万随机采样点验证：判定函数 vs 渲染扇形多边形，零不一致（排除多边形离散化边界点）。
  - 副作用：玩家用三连击时范围从"方形对角 ~5.8 格"变成 3.0 格扇形（ENTITY_REACH 默认 3）——这才是近战该有的范围。
- **核心 mod 侧相应清理**：删掉 `SHAPE_CONE_BOX` / `showConeBox` / `clipHalfPlane` / `TARGET_HALF_WIDTH`，物理三连击回落成干净的 `showSector(getMeleeReach(), 60°)`。
  - 注意：**必须同时更新附属 mod 的 jar**，否则运行时判定还是旧的方块 AABB，红圈又会偏小。
- **站桩化**：用户要求"跑动的 AI 暂时不需要，三个技能都站桩"。
  - `PhantomHeroBowAttackGoal` 删掉风筝/后退/横向绕圈（kiteCycleTimer、strafe、moveTo 全部移除），构造签名简化为 `(mob, attackInterval)`，flag 只保留 LOOK，每 tick `navigation.stop()`，只做 转向 + 拉弓 8 tick + 射击。
  - `PHYSICAL_RANGE` 6.0 → 4.5（略大于判定半径 3.5，站桩时玩家靠过来才吃得到近战）。
- **构建链路**：改附属后必须 `附属 gradlew build` → 把 `附属/build/libs/*.jar` 拷到 `核心/libs/` → 再 `核心 gradlew build`。两个 jar 都要给用户。

## 幻影勇者：第五轮（提示圈残留）

- **残留根因**：`PhantomTelegraphRenderer.TELEGRAPHS` 是「只追加、只靠自然过期」的列表。三连击一次技能会发 4 个提示（1 个预警 + 3 次命中闪光），旧的没过期就被新的盖在下面 → 看起来像上一个动作的提示残留到下一个动作。
  → 修法：`addTelegraph()` 里先 `removeIf(t -> t.ownerId == ownerId)`，**同一个施法者同时只允许存在一个提示**，新的直接顶掉旧的（顺带解决网络包延迟/乱序）。
- **新增清除指令**：`PhantomTelegraphPacket.SHAPE_CLEAR = -1` + `PhantomTelegraph.clear(world, owner)`，`PhantomHeroComboGoal.stop()` 里调用一次主动抹掉残留。
- **顺带修的 3 个小问题**：
  1. `canContinueToUse()` 原来是 `tick < getTotalTicks()`，而最后一段命中就发生在 `tick == getTotalTicks()` → GoalSelector 会先 stop()，**第三段伤害永远打不出来**。改成 `tick <= getTotalTicks() + FLASH_TICKS`（后者让最后的命中闪光播完再 stop，否则 stop 里的 clear 会立刻抹掉它）。
  2. 命中闪光用的 `COLOR_FLASH` alpha = 1，原代码只在 `a < 1.0F` 时才渐隐 → 满红一直显示然后整块突然消失，观感像卡住。改成统一渐隐 `a *= 0.35 + 0.65 * (tick/maxDuration)`。
  3. 渲染循环改成 Iterator：施法者已不在世界（死亡/卸载）时 `it.remove()`，防止实体没了提示还留着。

## 幻影勇者：第六轮（法术动画残留 + gradle 缓存损坏）

- **魔法三连击动画残留的根因（重要）**：`MAGIC_COMBO` 用的是铁魔法的 `continuous_thrust_one_handed` / `long_cast`，这两个是**循环动画**。`KeyframeAnimationPlayer` 对循环动画的 `isActive()` **恒为 true**，而 `PhantomHeroModel` 原本只靠 `!applier.isActive()` 判断结束 → 播完再也停不下来，手一直举着。物理三连击用 `attack1/3/4`（非循环短动画）所以没这问题。
  → 修法：新增 `DATA_ANIM_DURATION`(int)，服务端 `playSpellAnimation(rl, durationTicks)` 一起下发时长；模型用 `animTicksLeft` 倒计时，到点强制 `applier = null` 并回到原版姿势。duration <= 0 才走原来的 isActive() 逻辑。
  → 注意设置顺序：duration 必须比 seq 先写（客户端靠 seq 变化才去读 duration）。
  → `ComboGoal.beginSegment` 传 `COMBO_TICK_DELAY[index]`；`stop()` 里 `clearSpellAnimation()` 兜底（目标中途死亡被中断的情况）。
- **教训：不要中途 kill gradle 进程**。强杀会让 `~/.gradle/caches/8.8/transforms/<hash>/` 只留下半成品的 `transformed/` 而没有 `metadata.bin`，之后构建就报"系统找不到指定的文件"。
  → 修复：扫出所有缺 `metadata.bin` 的 transforms 条目（`for d in */; do [ -f "$d/metadata.bin" ] || echo BROKEN; done`）直接删目录，gradle 会自动重建。transforms 是纯派生缓存，删了不丢任何东西。
- 用户偏好：**打包（gradlew build）由用户自己跑**，我只做 compileJava 验证。

## 幻影勇者：第七轮（拉弓动画 + 改回主动贴脸近战）

- **拉弓姿势**：Alex 的弓箭动画是 `FastBossModel.setupAnim` 里手写的（`isUsingItem() && getMainHandItem() instanceof BowItem` → 双臂摆到 `-π/2` 的持弓/拉弦角度），**不是**原版 `HumanoidModel.ArmPose.BOW_AND_ARROW`——原版那条路要靠 `getUseItem()`，该字段对非玩家实体是服务端独有的。
  → 在 `PhantomHeroModel` 的 `applier == null` 分支里加了完全一样的拉弓姿势（右手持弓 yRot -0.4，左手拉弦 yRot +0.4）。弓弦拉开的视觉靠 `BowItem` 的 pull 属性，客户端 `useItemRemaining` 会随 tick 递减，8 tick 后 pull≈0.4，和 Alex 一致。
- **行为从「全站桩」改回「主动贴脸近战」**：
  - 新增 `PhantomHeroApproachGoal`（MOVE+LOOK，speedModifier 1.0）：只要距离 > `MELEE_ENGAGE_RANGE`(2.4) 就朝目标寻路（每 4~9 tick 重算一次路径）。
  - `PhantomHeroComboGoal.canUse()`：`distance <= 4.5` → 物理三连击（默认手段）；否则只有 `isTargetFleeing() && distance ∈ [8, 18]` 才用魔法三连击。
  - `PhantomHeroBowAttackGoal.canUse()`：新增 `isTargetFleeing() && distance >= 6.0`。
  - 优先级：Combo(1) > Bow(2) > Approach(3) > 随机游荡(4)；MOVE flag 冲突 → 高优先级直接把低优先级顶掉（已确认 `GoalSelector.tick` 的 goalUpdate 会 stop 掉占用同 flag 的旧 goal）。
- **"玩家主动远离"检测**在 `BossPhantomHero.updateFleeState()`（每 tick 服务端执行）：比对本 tick 与上一 tick 的 `distanceTo(target)`，增量 > 0.05 格/tick 就 `fleeTicks += 2`（上限 40），否则 `-1`。只看**距离变化量**不看绝对值，这样"站得远但不动"不会被误判成逃跑，Boss 会自己走过去打近战。
- **顺带修的属性 bug**：技能期间的站桩锁原来是 `ADDITION -9.0` 的 MOVEMENT_SPEED 修饰器 → 属性值变成负数。`MoveControl#tick` 里 `speed = speedModifier * 属性值`，负速度会让方向向量反号、Boss 往后退。改成 `MULTIPLY_TOTAL -1.0`（直接乘 0，与属性基准无关）。
- 另一个已确认的事实：`navigation.moveTo(entity, speed)` 的 speed 是**倍率**不是绝对值（`MoveControl#tick` 里再乘 MOVEMENT_SPEED 属性），原版 `MeleeAttackGoal` 用 1.0。

## 幻影勇者：第八轮（TACZ 狙击 + 剑盾状态，学自女仆模组）

- **TACZ 依赖**：`build.gradle` 加 `implementation fg.deobf("curse.maven:timeless-and-classics-zero-1028108:7401617")`（与女仆模组同一个 curse maven 坐标，本地 gradle 缓存里已有，可 --offline 解析）。运行时用 `ModList.get().isLoaded("tacz")` 守卫，没装就不注册狙击 goal。
- **TACZ 开枪流程**（学自女仆 `compat/gun/tacz/TacInnerCompat#performGunAttack`）：
  - 枪不是一枪一个物品：统一是 `ModItems.MODERN_KINETIC_GUN`，具体哪把枪写在 NBT 里 → `new ItemStack(...)` 后 `IGun#setGunId(stack, gunId)`。
  - **AWM 的 id 是 `tacz:ai_awp`（不是 awm！）** —— 默认枪包文件 `ai_awp_data.json`，en_us 里 `tacz.gun.ai_awp.name = "Accuracy International AWM"`。已做兜底：该 id 不存在时遍历 `TimelessAPI.getAllCommonGunIndex()` 找任意 type=="sniper" 的枪。
  - 开枪：`IGunOperator.fromLivingEntity(shooter).shoot(() -> pitch, () -> yaw)`，yaw = `-atan2(dx,dz)`、pitch = `-atan2(dy, sqrt(dx²+dz²))`，和女仆一模一样。
  - 狙击枪必须先 `aim(true)` 等 `GunData#getAimTime()` 秒，否则打不准。
  - `ShootResult` 逐项处理：`NOT_DRAW → draw()`、`NEED_BOLT → bolt()`、`NO_AMMO → reload()`。AWM 是 manual_action（bolt_action_time 0.9s）。
  - **弹药**：女仆是从背包找弹药（`ItemsUtil.findStackSlot` + reload），Boss 没有背包，改用 TACZ 的 dummy ammo：`IGun#setDummyAmmoAmount(stack, getMaxDummyAmmoAmount)` + `setCurrentAmmoCount` + `setBulletInBarrel(true)`，每次开枪前填满。
  - 全部 `com.tacz.*` 引用封装在 `com.main.fast.compat.PhantomTacGun` 里，对外只暴露 `isAvailable()` 和自定义 `ShotResult` 枚举，避免没装 TACZ 时 NoClassDefFoundError。
- **新增 `PhantomHeroSniperGoal`**（优先级 2）：距离 16~64 触发，前摇 = 枪械自身 `getAimTime()*20` + 40 tick 额外蓄力，期间画沿视线的细红色直线（`showBeam`，半宽 0.5，长度 = 到目标距离 + 10）。冷却 12s。
- **新增 `PhantomHeroShieldRushGoal`**（优先级 3）：**状态型技能**，触发距离 12，进入后持续 6s（一边举盾一边像僵尸一样追着打，`doHurtTarget` + swing，间隔 20 tick），到点强制结束并进 5s 冷却。
- **盾牌逻辑**（学自女仆 `MaidUseShieldTask` / `EntityMaid`）：
  - 举盾 = `startUsingItem(InteractionHand.OFF_HAND)`，放下 = `stopUsingItem()`。
  - `canUseShield()` 用 `offhand.canPerformAction(ToolActions.SHIELD_BLOCK)`（女仆还查了 `getCooldowns()`，但那是 Player 专属 API，生物没有，已去掉）。
  - 新增 `WEAPON_SHIELD`(4) 状态：主手钻石剑 + 副手盾；`applyWeaponItem` 现在同时设主手和副手（之前只设主手）。
  - 被动举盾（女仆 `hurt()` 同款）：被 `DamageTypeTags.IS_PROJECTILE` 打中且手上有盾 → 举盾 3s。
  - 覆写 `isBlocking()`：原版靠 `getUseItem()`（非玩家实体服务端独有），改成 `isUsingItem() && getUsedItemHand()==OFF_HAND && 副手能 SHIELD_BLOCK`，两边都能对上。
  - **模型**：原版没有任何地方给非玩家实体设置 `HumanoidModel` 的 armPose（只有玩家渲染器会设），所以 `PhantomHeroModel` 在 `super.setupAnim()` **之前**手动设 `leftArmPose = ArmPose.BLOCK`（主手右、盾在副手=左手）。
- 优先级最终：Float(0) > Combo(1) > Sniper(2) > ShieldRush(3) > Bow(4) > Approach(5) > 游荡(6) > Look(7/8)。

## 幻影勇者：第九轮（近战距离改原版公式 + 三连击红圈窗口对齐）

用户反馈：近战攻击距离比玩家长（"默认类似僵尸那种应该比玩家短"），物理三连击也比红圈显示得长。

- **剑盾近战距离（真 bug）**：`PhantomHeroShieldRushGoal` 原来写成 `boss.distanceTo(target) <= ATTACK_REACH(3.0D)`，这是**中心到中心** 3.0 格。原版僵尸 `MeleeAttackGoal#getAttackReachSqr` = `(mob.getBbWidth()*2)^2 + target.getBbWidth()` = 1.2² + 0.6 = 2.04 → 中心距 **~1.43**。Boss 宽 0.6（`FastEntities` 注册 0.6F/1.95F）算出来也是 1.43，原来那 3.0 是僵尸的 2 倍多。
  → 修法：`BossPhantomHero` 新增 `public double getAttackReachSqr(LivingEntity target)`（原版公式原样复刻），ShieldRushGoal 改为 `boss.distanceToSqr(target) <= boss.getAttackReachSqr(target)`，删掉 `ATTACK_REACH` 常量。
  → 注意：BossPhantomHero 完全覆写了 `registerGoals()` 且没调 super，所以 `FastBossEntity` 里那个 `MeleeAttackGoal(1.2D, true)` **不会生效**，近战距离只由 ShieldRushGoal 决定。
- **物理三连击"判定比显示长"**：几何上判定和红圈本来就是同源（都从 `position()` 水平出发、半径 = ENTITY_REACH = 3.5、半角 60°），真正的问题是**时间窗口**：
  1. 起手距离 `PHYSICAL_RANGE = 4.5` > 判定半径 3.5 → Boss 站在红圈外面就把刀抡起来了。
  2. 红圈只在起手 20 tick（1 秒）内存在，而三段命中分别在 tick **28 / 36 / 50** → 中间 30 多 tick 完全没提示却持续挨打。
  → 修法：
    - 起手距离换成 `private double physicalRange() { return Math.max(1.0F, boss.getMeleeReach()); }`（= 判定半径，圈里才起手）。
    - `start()` 的红圈时长 `WARNING_TICKS` → `WARNING_TICKS + COMBO_TICK_DELAY[0]`（盖到第一次命中）。
    - `tick()` 里 tick==28 / tick==36 命中后**立刻重发**下一段红圈（时长 = D[1]/D[2]），红圈全程覆盖每一次判定。
    - `finishSegment(index)` 只在 `index == 2`（最后一击）发 `COLOR_FLASH`。中间的闪光会顶掉刚铺好的红圈（渲染器同 owner 去重），4 tick 后圈就消失 → 又变回"显示比判定短"。
    - 中间两段的"打击感"由重发红圈时 alpha 回满（渲染器 `a *= 0.35 + 0.65*(tick/maxDuration)`）提供。
- **未改**：`ENTITY_REACH` 仍是 3.5（红圈半径跟着一起走，两侧始终一致）；`MELEE_ENGAGE_RANGE` 仍 2.4（只影响无技能时的接近，不影响攻击距离）。
- 用户仍然自己跑 `gradlew build`（且改附属 jar 时要先编附属→拷 libs→再编核心）。

## 幻影勇者：第十轮（盾牌格挡：补音效 + 免击飞）

用户反馈：Boss 举盾格挡时**没有音效**，而且**格挡还会被击飞**。

- **根因**：原版盾牌格挡那条链路对非玩家实体是走不通的 ——
  1. 原版 `LivingEntity#isBlocking()` 要求盾「举起满 5 tick」才算数（MC-100949），Boss 常常是挨打前一瞬才切进剑盾状态，永远差那 5 tick；
  2. 原版成功格挡时的 `item.shield.block` 音效属于玩家链路，非玩家实体听不到（**女仆模组也是自己补的**：`EntityMaid#hurtCurrentlyUsedShield` 里手动 `playSound(SHIELD_BLOCK)`，注释写「调整原版的机制」）；
  3. 原版 `isDamageSourceBlocked` 要求攻击源严格落在视线正前方（±90°），Boss 作为 AI 站偏一点就完全挡不住 → 伤害全额 + 被击退。
- **修法**（全在 `BossPhantomHero`）：
  1. **`hurt()` 显式接管格挡结算**：`isShieldBlocking(source)` 为真时 → `hurtCurrentlyUsedShield(amount)` 扣耐久+出音效 → `blockUsingShield(attacker)` 交给攻击者侧处理（斧头破盾）→ **`return false`**（这一下完全无效，击退/着火/凋零等附带效果一并失效）。开头补 `isInvulnerableTo || isDeadOrDying` 早退。
  2. **新增 `isShieldBlocking(DamageSource)`**：举盾 + 非 `BYPASSES_ARMOR` + 非穿透箭（`AbstractArrow#getPierceLevel() > 0`）+ 有 `getSourcePosition()` + 攻击源在**身前 110°**内（比原版 ±90° 宽松，常量 `SHIELD_BLOCK_ARC_DEGREES`）。贴脸（水平距离≈0）直接算挡住。背后仍挡不住，保留绕背破盾玩法。
  3. **覆写 `hurtCurrentlyUsedShield(float)`**（女仆同款）：用 `this.useItem.canPerformAction(ToolActions.SHIELD_BLOCK)` 判断；`damage >= 3` 时 `hurtAndBreak(1+floor(damage))` 扣耐久（回调 `broadcastBreakEvent` + `stopUsingItem`），盾碎 → `setItemSlot(hand对应的槽, EMPTY)` + `useItem = EMPTY` + `playSound(SHIELD_BREAK)`；否则 `playSound(SHIELD_BLOCK, 1.0, 1.0)`。
  4. `isBlocking()` 保持「isUsingItem + OFF_HAND + 副手能 SHIELD_BLOCK」，**故意去掉原版 5 tick 门槛**（女仆注释同款）。
- 依赖 import 新增：`SoundEvents`、`Entity`、`EquipmentSlot`（`AbstractArrow`、`ItemStack`、`ToolActions`、`Mth`、`Vec3` 本来就有）。
- `compileJava --offline` 通过（只有一条 `PathfinderMobMixin` 的旧 deprecation 警告，与本次无关）。

## 幻影勇者：第十一轮（半血转化 + 二阶段随机选招 + 常驻盾）

用户需求：
- 半血触发转化 —— 若单次伤害会打过半血，则**锁定在半血**然后进转化阶段；
- 二阶段：常驻盾牌，**盾碎 5 秒后自动修复**；
- 近战三连击期间**会移动**（一阶段是站桩）；
- 二阶段近战距离下**不再复读物理三连击**，而是**从所有技能随机抽两个**放完，然后回剑盾（剑盾本身不算，它算半个常驻）。

**BossPhantomHero 新增：**
- `phase`(1/2) + `DATA_PHASE`(int, 同步给客户端)；`transitionTicks` / `shieldBreakCooldown` / `attackSelection` / `attackSelectionTick` / `pendingAttacks`（后三个是选招状态机）。
- 常量：`PHASE_TWO_HEALTH_RATIO=0.5`、`SELECTION_TICKS=10`、`TRANSITION_TICKS=60`、`SHIELD_REGEN_TICKS=20*5`。
- `clampToPhaseThreshold(source, amount)`：在 `hurt()` 里**格挡判定之前**调用。若 `getHealth()-amount < maxHealth*0.5` → `allowed = getHealth()-threshold`（只扣到半血）→ `enterPhaseTwo()` → 返回 allowed；allowed 为 0（正好半血）时上层走 `super.hurt(source, 0.0F)`（原版「无敌帧式」空结算，返回 true，特效/击退照常）。跳过条件：已二阶段 / 正在转化 / `BYPASSES_INVULNERABILITY`。
- `enterPhaseTwo()`：置 `phase=2`、`DATA_PHASE=2`、`transitionTicks=60`、清各技能冷却、`pendingAttacks=0`、**显式发一面满耐久盾**（不能靠 setWeapon 补，见下）、`setWeapon(WEAPON_SHIELD)`、`startUsingItem(OFF_HAND)`、播 `TOTEM_USE`。
- `tickPhase()`：转化倒计时；归零时置 `attackSelection=true, pendingAttacks=2`；之后每 tick 推进 `attackSelectionTick`，到 `SELECTION_TICKS` 清除。在 `tick()` 里「!isClientSide」分支和 `updateFleeState()` 一起调。
- `tickShieldMaintenance()`：二阶段每 tick 跑。**只看副手有没有盾**（`isShieldEquipped()`），不关心当前拿什么武器 —— 这样放技能的间隙倒计时也照走。盾没了 → 计时 5 秒 → `setItemInHand(OFF_HAND, SHIELD)` + 播 `ANVIL_USE`（只有当前是 WEAPON_SHIELD 姿势才顺手举盾）。
- `restoreShieldStance()`：补主手钻石剑（`SwordItem` 判断）+ 有盾就举。**刻意不补盾**，否则修复机制成摆设。
- **`applyWeaponItem()` 重写副手逻辑**（关键）：一阶段 `WEAPON_SHIELD` → 没盾发新盾；**二阶段 `WEAPON_SHIELD` → 保留已有盾，没盾就空着等修复**；二阶段非剑盾武器 → 有盾就留着（原版单手武器也能举盾）；一阶段非剑盾 → 空副手。
- `getAttackReachSqr(LivingEntity)`（上一轮加的）继续用于剑盾近战距离。

**PhantomHeroComboGoal：**
- 新增 `forceStart(boolean magic)` + `forced`/`forcedMagic`：二阶段选招用，绕开距离/冷却/选招空档门槛并**钉死形态**（否则近战距离下抽到魔法会被距离判断掰回物理）。
- `canUse()` 新增：`transitionTicks>0` 拒绝；二阶段近战距离返回 false（让位给选招调度）；`attackSelection` 拒绝。
- 新增 `phaseTwoCast`（二阶段选招打出）和 `movingCast`（本次是否移动，**只读，不被 stop() 改**）。
- `start()`：`movingCast = isPhaseTwo() && physical` → 不上站桩锁 `SPEED_LOCK`，只上 `KB_LOCK`（拆出 `applyKnockbackLock()`）。
- `tick()`：`movingCast` 时前摇+第一段之前 `moveTo(target, 1.0)`，之后 `stop()`（避免把目标推出扇形）；非 movingCast 每 tick `navigation.stop()`。
- `stop()`：`phaseTwoCast` 分支 → `pendingAttacks--`、`attackSelection=true`、回 `WEAPON_SHIELD`、提前 return；否则走原一阶段收尾（回弓 + shieldRushCooldown）。

**PhantomHeroSniperGoal：**
- 新增 `forceStart()` + `forced`：绕开距离/冷却/LOS 门槛。
- `canUse()` 新增 `transitionTicks>0` 拒绝、二阶段近战距离拒绝、`attackSelection` 拒绝。
- `stop()`：二阶段 → 回 `WEAPON_SHIELD` + 扣配额 + 置选招空档；否则回弓。
- `tick()` 仍站桩（用户只要求「近战三连击期间移动」）。

**PhantomHeroBowAttackGoal：**
- 新增 `forceStart()` + `forced`/`forcedDone`：绕开 `isTargetFleeing()` 和 6 格起射距离（近战距离也能拉弓）。
- `canUse()` 新增 `transitionTicks` / 二阶段近战距离 / `attackSelection` 拒绝。
- `canContinueToUse()`：forced 时靠 `forcedDone` 结束（射一箭一轮）。
- `tick()`：forced 射完一箭后 `forcedDone=true`。
- `stop()`：forced（二阶段）→ 回 `WEAPON_SHIELD` + 扣配额 + 置选招空档。

**PhantomHeroShieldRushGoal：**
- `canUse()`：`transitionTicks>0` 拒绝；**一阶段才看冷却**；二阶段 `attackSelection || pendingAttacks>0` 拒绝。
- `canContinueToUse()`：二阶段不设时限（否则会在剑盾/空手间反复横跳），只在转化中/选招中/欠技能时让位。
- `start()`：二阶段走 `restoreShieldStance()`（保留盾），一阶段才 `setWeapon`。
- `stop()`：二阶段**什么都不动**（主手剑、副手盾保持，无冷却），一阶段才放盾+回弓+进冷却。

**PhantomHeroPhaseTwoGoal（新文件）：**
- 优先级 1（Float 之上、Combo 之下），`setFlags(noneOf)` —— 不抢 MOVE/LOOK，只做调度。
- `canUse/canContinueToUse`：二阶段 + 非转化 + `pendingAttacks>0` + 有目标 + **距离 ≤ meleeReach**（只有近战距离才走选招；玩家跑远时仍走一阶段那套魔法/弓箭追击）。
- `tick()`：`comboCooldown>0 || sniperCooldown>0 || isUsingItem()` 时等待（有技能在放）；`attackSelection` 等待；`delay` 倒数；然后 `pickAndStart()`。
- `pickAndStart()`：`nextInt(4)` 抽 物理/魔法/狙击/弓箭；狙击在没装 TACZ 时回落物理；起手后**立刻** `attackSelection=true` 防同 tick 重复抽；`PICK_DELAY=6`。
- **`BossPhantomHero.setPhaseTwoGoals(combo, sniper, bow)`**：注册 goal 时把实例存下来（GoalSelector 外面拿不到实例）。

**Goal 优先级最终**：Float(0) > PhaseTwo(1) > Combo(2) > Sniper(3) > ShieldRush(4) > Bow(5) > Approach(6) > 游荡(7) > Look(8/9)。

**踩到的坑 / 结论：**
- `attackSelectionTick` 必须是 public（多个 goal 包外访问）。
- 转化演出期间所有攻击 goal 都靠 `transitionTicks>0` 统一拒绝，比逐个加标志干净。
- 二阶段「盾常驻」和「盾碎 5 秒修复」是**一对矛盾**：只要 `applyWeaponItem` 在任何换武器/回姿势路径上给新盾，修复机制就永远不触发。所以只有在 `enterPhaseTwo()` 里显式发一次盾，其余路径一律「有就留、没有就空着」。
- `compileJava --offline` 通过。

## 灾变兼容：移除 Boss 的「箭矢免疫」

目标：用 mixin 干掉 L_Ender's Cataclysm（3.31）里 Boss 的投射物免疫。

- **重要认知：免疫不在 mixin 里**。灾变自己只有 13 个 mixin（眩晕/物品/结构/accessor），跟 Boss 免疫无关；真正的免疫写在各 Boss 实体对 `hurt(DamageSource, float)`（SRG 名 `m_6469_`）的重写里，形如
  `Entity e = source.getDirectEntity(); if (e instanceof AbstractArrow) return false;`
- **伤害标签辨析**：`f_268738_` = `BYPASSES_INVULNERABILITY`（不是投射物！），`f_268524_` = `IS_PROJECTILE`。映射表在 `~/.gradle/caches/forge_gradle/minecraft_repo/versions/1.20.1/`（`mcp_mappings.tsrg` obf↔SRG + `client_mappings.txt` SRG↔人类名，交叉比对即得）。
- **手法**：`@Redirect` 注入 `DamageSource.getDirectEntity()`（SRG `m_7640_`），把箭矢来源替换成 `null`，免疫分支自然失效，其余逻辑（阶段无敌、动态减伤）零影响。全部 `remap = false` + SRG 字面量，因此**不需要灾变编译依赖**。
- **范围**（用户明确只保留「箭矢」）：远古遗魂 / 末影守卫 / 先驱者 三个；末影守卫的潜影贝子弹一并收敛为只判 `AbstractArrow`。已删除毒镖（科博迪亚特/瓦吉特/科博莱顿）与自伤保护（大小利维坦）共 5 个 mixin。
- 文件：`src/main/java/com/main/fast/mixin/cataclysm/`（`CataclysmProjectiles` 工具类 + 3 个 Mixin），配置 `fast.cataclysm.mixins.json`（`required: false`，没装灾变不影响本模组）。
- **构建关键坑（重要）**：mixin 第三方模组但不加依赖时，Mixin AP 会因「找不到目标类」直接报 `Mixin target ... could not be found`（**错误级**）。`-AdisableTargetValidator` **不管用**——该消息是 `MIXIN_SOFT_TARGET_NOT_FOUND`，要用 AP 的 `MSG_` 系列选项改等级：
  ```gradle
  tasks.withType(JavaCompile).configureEach {
      options.compilerArgs += ['-AMSG_MIXIN_SOFT_TARGET_NOT_FOUND=warning', '-AdisableTargetValidator']
  }
  ```
  （格式 `-AMSG_<枚举名>=note|warning|error|disabled`，源码见 `IMessagerEx$MessageType.applyOptions`。）
- **构建速度**：`gradle.properties` 里 `org.gradle.daemon=false` → 每次编译都冷启动单次 JVM（日志 "single-use Daemon process will be forked"），一两分钟起步，不是卡死。加 `--offline` 且任务 UP-TO-DATE 时约 21s 完成。不要中途 kill（见第六轮 transforms 缓存损坏的教训）。

## 幻影勇者：第十一轮（三连击「第 4 段」）

用户反馈：物理三连击像是 4 段（伤害也是 4 次），魔法三连击红圈也有 4 段但伤害只有 3 段。

- **先证伪**：连击本体只有 3 段。直接反编译 `build/libs/fast-1.20.1-forge-0.0.1.jar` 核对——`PhantomHeroAnimations.COMBO_TICK_DELAY` 是 `iconst_3 / {8,8,14}`，`PhantomHeroComboGoal.tick()` 里 `finishSegment` 只被 `invokevirtual` 3 次。**排查结论要落到运行产物上，别只看源码**。
- **根因 1（红圈 4 段）**：`tick()` 发 3 次预警圈，`finishSegment(2)` 又额外发一次不透明的「命中闪光」→ 一共 4 次亮起。改法：删掉闪光那次，第三段红圈时长改成 `D[2] + FLASH_TICKS` 自己渐隐收尾，`finishSegment(int index)` 参数一并去掉（只剩补发逻辑）。
- **根因 2（近战 4 下）**：`PhantomHeroShieldRushGoal`（优先级 3）的 `start()` 里 `attackCooldown = 0`，物理三连击贴脸打完立刻被它接手补一刀；而魔法三连击在 8~18 格外放，剑盾突进够不着 → 只有物理看起来是 4 段。改法：`PhantomHeroComboGoal.stop()` 里 `boss.shieldRushCooldown = Math.max(..., COMBO_RECOVERY_TICKS=30)`，三连击后留 1.5s 收招。
- `PhantomTelegraph.COLOR_FLASH` 仍被 `PhantomHeroSniperGoal` 使用，不能删。
- `compileJava --offline` 通过（1m，只有灾变 mixin 的软目标警告 + PathfinderMobMixin 的旧 deprecation）。

## 幻影勇者：第十三轮（二阶段 7 条问题清单修复）

用户给的 7 条问题，逐条落地：

1. **转阶段不该是无敌** → `clampToPhaseThreshold` 不再削伤害，只做「触发器」；`enterPhaseTwo(DamageSource, float)` 新增伤害入参，用 `setHealth(max(threshold, 当前血 - amount))` 精确把血线锁在 50%（溢出伤害作废，但这一下的伤害数字/击退照常）。同时**不再要求 `transitionTicks <= 0`**——否则 3 秒演出期间玩家继续输出能把它打死。
2. **二阶段全程副手盾 + 全程格挡 + 碎后 5 秒修** → `isShieldBlockingState()` 简化成只看 `hasShield()`（一/二阶段都不再看 `isUsingItem`）；`isBlocking()` 覆写改为直接复用 `isShieldBlockingState()`，客户端渲染与实际判定同源。
3. **盾渲染没了但还格挡（根因）** → 有两处「裸 `setItemInHand(OFF_HAND, SHIELD)`」漏同步 `DATA_SHIELD`：`enterPhaseTwo` 补盾、`tickShieldMaintenance` 5 秒补盾。全部改走 `setOffhandShield`，让副手物品与同步字段成对更新。
   - **踩坑**：一度以为根因是 `swapItemWithOffhand()`，写了覆写 → 编译报「方法不会覆盖超类型」。查 `srg_to_official_1.20.1.tsrg` 才知道 **1.20.1 根本没有 `swapItemWithOffhand`**（那是 1.20.2+ 才改的名）；1.20.1 里 `LivingEntity.m_21253_` = `releaseUsingItem`，副手交换逻辑在 `Player` 里。已删除该覆写。
