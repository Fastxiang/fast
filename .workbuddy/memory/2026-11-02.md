## 勇者皮肤「第二层没渲染」的真正原因 + 修复
- 现象：贴图换成粉发+外套之后，游戏里只有头发（hat）出现，外套 / 袖子 / 裤腿完全没有。
- 根因（已用 MC 源码确认）：`HumanoidModel extends AgeableListModel`，后者的 `renderToBuffer`
  **只遍历 `headParts()` + `bodyParts()`**；而 `PlayerModel.createMesh` 把 `jacket / right_sleeve /
  left_sleeve / right_pants / left_pants` 挂在 **root** 上，既不在 headParts 也不在 bodyParts
  （bodyParts 只有 body / arms / legs / hat）→ 这五个部件从来没被画过。
  顺带也解释了「袖子不动」：它们不在骨骼树里，`HumanoidModel.setupAnim` 也不会 copyFrom。
- 修法：新增 `entity/client/PhantomHeroLayers`，拿 `PlayerModel.createMesh(CubeDeformation.NONE, false)`
  的网格，把五个第二层部件 **改挂到对应部件下**（外套→body、袖子→arm、裤腿→leg，PartPose.ZERO），
  `hat` 仍留 root（HumanoidModel 读 root.getChild("hat")）；同时把第二层加厚
  （hat 0.5→0.9，cloth 0.25→0.5）。`ModelPart.render` 会递归渲染 children，所以挂上去就会画、也会跟着动。
- `ear` / `cloak` 两个占位方块 `skipDraw = true`（在 bake 出来的 ModelPart 上设，PartDefinition 没有这字段）。
- 踩坑记录：`LayerDefinition` 没有 `bake(int,int)`，只有 `create(mesh,w,h)` + `bakeRoot()`；
  `PlayerModel.createMesh(Pose,boolean)` 不存在，1.20.1 是 `createMesh(CubeDeformation, boolean)`。

## 商店：两处文字裁切 + 分类顺序 API + 拖拽排序
- **裁切根因（用 `screenshots/aui` 逐帧量像素确认，别靠猜）**：
  ① 标题「森林杂货铺」顶部被削平 —— `.sign::before` 那条草方块是绝对定位、画在文字上层，
     而 `.sign` 的 `padding-top` 只有 5px，草条总高 10px（内容 6 + 描边 2×2）→ 压住字顶。
     修法：`padding: 11px 8px 4px`（10 + 1 呼吸）。
  ② 左上「今天也要好好冒险呀！」最后一个「！」被金币图标盖住 —— 左栏 156px，
     内容宽只有 138px，提示语 ~110px + 「● 56,865」~55px 一行塞不下，flex 把提示语压窄。
     修法：`.wallet` 加 `flex-wrap` + `.wallet-tip { width:100% }`（独占一行），
     `.wallet-money { width:100%; justify-content:flex-end }` 留第二行右侧。
     ⚠️ 折行后的 flex 行里 `margin-left:auto` AUI 不认，别指望它。
- **分类顺序 API**：`ShopManager.setCategoryOrder(shopId, String...)` / `ShopRegisterEvent.setCategoryOrder`（KubeJS 直接调）。
  顺序随 `PacketSyncShopData` 一起下发（`categoryOrder`）→ `ClientShopCache.getCategoryOrder` →
  `FastShopUI.getDefaultOrder()`。页面只拿「显式指定过」的 key，剩下的按注册顺序补齐，
  所以新增分类不用回来改表。
- **玩家自定义顺序**：按 UUID 存 `config/fast/shop_order/<uuid>.txt`（换行分隔），
  桥接 `FastShopUI.getPersonalOrder()/setPersonalOrder()`；localStorage 只作兜底（Forge 上写不进去）。
  页面排序 = 玩家顺序 → 作者顺序 → 注册顺序（`fsSortCategories`，必须自己带次级键，Rhino 的 sort 不稳定）。
  保存时要把「当前这一档没渲染出来」的分类按旧顺序补回去，否则买卖两档会互相覆盖。
- **拖拽手感（用户明确要求「像把物品拎起来」）**：
  越过死区 → 真身 `appendChild(document.body)` + `position:fixed` + 原位留 `cloneNode(false)` 的空壳；
  虚影用 `transform: translate(dx,dy)` 跟手（**不要每帧改 left/top**，那是布局属性，会又卡又追不上手）。
  命中判定**不要自己算格子**：直接取 `event.target` 沿 `parentElement` 找 `.category-option`，
  空档 `insertBefore` 到它前面。class 必须按空格切词精确比 ——
  `indexOf("category-option")` 会命中 `.category-option-name` 这类内层 span，把空壳插进按钮里。
  AUI 无 `document.elementFromPoint`，但 `Event.target` 就是命中的元素。
- 调试开关 `config/apricityui-client.toml` 的 `autoReload/aiAutoScreenshot` **只在启动时生效**，
  改完必须重启（本次就是先改文件、重启后才开始自动截图）。收工已恢复为 false。
